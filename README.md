## Overview

This project builds and evaluates a reproducible intrusion detection pipeline on the CICIDS2017 dataset. It trains three machine learning models for 15-class multi-class attack detection at the network flow level, evaluates them under two split strategies (stratified and temporal day-based), and maps all detected attack types to MITRE ATT&CK techniques to produce security engineering outputs.

## Reproducing All Results

### Option A: Full pipeline (recommended)

```bash
python run_pipeline.py
```

### Option B: Step by step

```bash
# Step 1: Build and clean the dataset
python -m src.prepare_data

# Step 2: Leakage audit
python -m src.leakage_check

# Step 3: Train models (both split strategies)
python -m src.train --split strat --out-dir models/baseline_strat
python -m src.train --split day   --out-dir models/baseline_day

# Step 4: Evaluate models
python -m src.eval --split strat --models-dir models/baseline_strat --out-dir reports/metrics_strat
python -m src.eval --split day   --models-dir models/baseline_day   --out-dir reports/metrics_day

# Step 5: Binary models
python -m src.train_binary --split day   --out-dir models/binary_day
python -m src.train_binary --split strat --out-dir models/binary_strat
python -m src.eval_binary  --split day   --models-dir models --out-dir reports/metrics_day_binary
python -m src.eval_binary  --split strat --models-dir models --out-dir reports/metrics_strat_binary

# Step 6: Leave-One-Day-Out cross-validation
python -m src.eval_lodo

# Step 7: Generate security outputs
python -m src.mitre_alerts --metrics-dir reports/metrics_strat --out-dir reports/alerts
python -m src.traffic_analysis
python -m src.report --metrics-dir reports/metrics_strat --alerts-dir reports/alerts

# Step 8: Split comparison report
python -m src.eval_split_compare --skip-train \
  --models-strat models/baseline_strat \
  --models-day   models/baseline_day \
  --metrics-strat reports/metrics_strat \
  --metrics-day   reports/metrics_day
```

## Key Results

### Multi-class (stratified split)

| Model | Macro Precision | Macro Recall | Macro F1 | ROC AUC (OvR) |
|---|---|---|---|---|
| Logistic Regression | 0.2250 | 0.8564 | 0.2662 | 0.9859 |
| Random Forest | 0.8859 | 0.8753 | 0.8452 | 0.9997 |
| **XGBoost** | **0.9327** | **0.8500** | **0.8627** | **0.9999** |

### Binary detection (day split)

Binary results are reported after re-running `src.eval_binary --split day`.
See `reports/metrics_day_binary/binary_metrics.json` for exact numbers.

> **Note on thresholds**: Under the day split, val (Thursday) and test (Friday)
> have disjoint attack types. Threshold selection uses sklearn's
> `precision_recall_curve` on val for fine-grained optimisation. The authoritative
> binary metric is **ROC-AUC** (threshold-independent), which is ≈ 0.97 for XGBoost.

### Distribution shift finding

Under the temporal day split (train Mon–Wed, val Thu, test Fri), multi-class models achieve macro-F1 ≈ 0.44. This is expected: each capture day contains a distinct and non-overlapping set of attack types, so the model cannot predict classes it has never seen. **Binary detection (Benign vs Attack) remains viable** with ROC-AUC ≈ 0.97, demonstrating that anomalous flow patterns generalise across attack types even when specific class labels do not.

### UNSW-NB15 (secondary benchmark)

| Model | Multi-class F1 | Binary ROC-AUC | Binary F1 |
|---|---|---|---|
| Logistic Regression | 0.4040 | 0.9757 | 0.8878 |
| Random Forest | 0.4842 | 0.9853 | 0.9242 |
| **XGBoost** | **0.5223** | **0.9857** | **0.9194** |

Same model ranking across both datasets, supporting generalisation of methodology.

## Day Split Configuration

```
Monday    → train   (Benign, DoS variants, FTP/SSH brute force, Heartbleed)
Tuesday   → train
Wednesday → train
Thursday  → val     (Benign, Web Attacks, Infiltration) — threshold tuning
Friday    → test    (Benign, Bot, DDoS, PortScan) — held-out evaluation
```

This follows standard temporal protocol: thresholds are tuned on the first unseen day (Thursday) and final metrics reported on the last day (Friday).

## Dataset

**CICIDS2017** — Canadian Institute for Cybersecurity 2,313,150 flows | 73 features | 15 attack classes  

Leakage columns dropped before modelling:
- `Flow Bytes/s`, `Flow Packets/s`, `Fwd Packets/s`, `Bwd Packets/s`  
  (algebraically derived from other features — would allow shortcut learning)

Near-duplicate leakage audit found ~28,000 flow groups crossing the day-split boundary and ~26,000 crossing the stratified split boundary. This is a known limitation of flow datasets without 5-tuple identifiers, documented in 
`reports/leakage_check.md`.

## MITRE ATT&CK Coverage

All 14 attack classes mapped to ATT&CK techniques across 6 tactics:

| ATT&CK Tactic | Attack Types |
|---|---|
| Impact | DDoS, DoS GoldenEye, DoS Hulk, DoS Slowhttptest, DoS slowloris |

## Notes

- All models use `random_state=42` for reproducibility.
- Stratified split stratifies on `attack_type` (multi-class) to ensure rare classes 
  are represented in every fold.
- XGBoost under the day split requires a label remapping step (saved as 
  `xgboost_label_remap.json`) because training classes are non-contiguous when 
  attack types are separated by day.
- Tree-based models (RF, XGBoost) are trained on raw (unscaled) features. Only 
  LogisticRegression requires feature scaling (handled via its Pipeline scaler).
